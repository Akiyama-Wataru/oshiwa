# 推し輪 実装計画

## 確定した設計

- 形態: スマートフォン優先のWebアプリ（PWA）
- 公開先: OpenAI Sitesの無料公開
- データ基盤: Supabase Free（Auth / Postgres / Storage / Realtime）
- 認証: メールアドレスとパスワード
- 参加方法: 管理者からの招待のみ。一般公開登録は提供しない
- 公開範囲: 同じグループのメンバーだけ
- 権限: `owner` / `admin` / `member`
- 投稿: 画像、本文、ハッシュタグ、複数の推しとの関連付け
- 交流: いいね、1階層の返信、通知、グループ内共有
- 対応端末: モバイルを主対象とし、デスクトップと横向きにも対応
- 検索エンジン: インデックス不可

## セキュリティ原則

- グループ境界は画面ではなくPostgreSQL RLSで強制する。
- 全データ行に`group_id`を保持し、親子関係もグループをまたげない複合外部キーで守る。
- 招待トークンは256-bitのランダム値を使い、DBにはSHA-256ハッシュだけを保存する。
- 招待はメール一致、確認済みメール、期限内、未使用、未取消を同時に満たす場合だけ受理する。
- Supabaseの秘密鍵はサーバー専用とし、ブラウザへ配信しない。
- 認証・API・投稿画像・個人化HTMLをService Workerへキャッシュしない。
- 保護ページは`private, no-store`とし、最終認可は必ずDBで行う。

## フェーズと合格条件

### フェーズ1: 基盤・デザイン・PWA

- 日本語UI、レスポンシブ入口、PWA manifest、オフライン案内
- セキュリティヘッダー、noindex、依存関係と型の整備
- 合格条件: unit/integration、80%以上のcoverage、typecheck、lint、本番ビルド、HTML応答、モバイル/デスクトップE2E、axe、コード/セキュリティ/WCAGレビュー

### フェーズ2: 認証・招待制グループ

- ログイン、ログアウト、招待確認、パスワード設定
- profiles / groups / memberships / invitations
- owner/admin/memberの権限、RLS、招待の一回限り処理
- 合格条件: 認証分岐、Cookie契約、RLS越境、招待再利用・期限・メール不一致、権限昇格、最終owner保護をテスト

### フェーズ3: 複数の推し・画像

- 複数の推し登録、編集、並び替え、メンバーカラー
- 画像圧縮、形式・容量・枚数制限、Storage RLS
- 合格条件: グループ越境、SVG拒否、偽装MIME、過大画像、削除権限、孤児ファイルをテスト

### フェーズ4: 投稿・タイムライン

- 最大4画像、本文、ハッシュタグ、推しとの関連付け
- グループ内タイムライン、絞り込み、編集、削除
- 合格条件: 入力境界、ページング、越境、所有権、親子のgroup整合をテスト

### フェーズ5: いいね・返信・通知・共有

- いいね切替、1階層返信、アプリ内通知、同一グループへの共有
- 合格条件: 二重いいね、同時実行、返信権限、通知権限、別グループ共有拒否をテスト

### フェーズ6: 管理・PWA仕上げ

- メンバー管理、招待取消、退出、再インストール、空/失敗/オフライン状態
- 合格条件: WCAG 2.2 AA、キーボード、320px、横向き、reduced motion、PWA更新をテスト

### フェーズ7: 総合検証

- 主要利用導線のE2E、RLS回帰、依存関係監査、秘密情報検査
- 合格条件: 全フェーズのテスト、レビュー、production buildがすべて合格

### フェーズ8: 公開・納品

- Supabase本番設定、Sites環境変数、保存済みバージョン、公開デプロイ
- 合格条件: 本番URLでログインから投稿・反応・招待まで確認し、運用手順を納品

## 進め方

各フェーズは「失敗するテスト追加 → 最小実装 → リファクタリング → 全テスト → レビュー」の順で進めます。1つでも必須テストが失敗した場合は、次のフェーズへ進みません。
